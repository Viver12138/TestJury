# 02 · 数据模型

> 版本：v0.2（并入评审修订：投票、证据溯源、Embedding Profile、持久化队列字段）

数据库：PostgreSQL 15+，扩展 `pgvector`；中文检索另需 `zhparser`（或 `pg_jieba`），未安装时退化为 `simple` 分词 + 精确匹配。

## 1. 实体关系

```
batches 1 ── n review_jobs
review_jobs 1 ── n model_runs        （3 次盲评 + 3 次投票 + 1 次仲裁 + 可能的重试）
review_jobs 1 ── n issues
issues 1 ── n issue_votes            （每个评审模型对每个候选问题的态度）
issues 1 ── 1 issue_embeddings
issues 1 ── n human_feedback
embedding_profiles 1 ── n kb_chunks / issue_embeddings
kb_documents / kb_rules / kb_chunks  ──  被报告通过 kb_refs 引用（逻辑引用，不建外键）
kb_gaps  ──  由评审中的"无依据判断"聚合产生
```

## 2. DDL

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
-- 中文分词（可选，未安装则用 simple 分词 + 精确匹配兜底）
-- CREATE EXTENSION IF NOT EXISTS zhparser;

-- ───────────── 批次 ─────────────
CREATE TABLE batches (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    status          TEXT NOT NULL DEFAULT 'queued',   -- queued|processing|done|partial|failed
    total           INT  NOT NULL DEFAULT 0,
    done            INT  NOT NULL DEFAULT 0,
    failed          INT  NOT NULL DEFAULT 0,
    caller_id       TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at     TIMESTAMPTZ
);

-- ───────────── 评审任务（同时充当任务队列） ─────────────
CREATE TABLE review_jobs (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    batch_id            UUID REFERENCES batches(id),
    case_id             TEXT NOT NULL,
    case_title          TEXT,
    module              TEXT,                        -- 规范化后的模块名；未命中知识库时仍记录原值
    status              TEXT NOT NULL DEFAULT 'queued', -- queued|processing|done|failed
    stage               TEXT,                        -- preprocess|kb_retrieve|blind_review|fusion|vote|arbitration|render
    verdict             TEXT,                        -- blocked|conditional|need_human|approved(仅人工)
    human_approved_by   TEXT,
    degraded            BOOLEAN NOT NULL DEFAULT FALSE,
    degraded_reasons    JSONB NOT NULL DEFAULT '[]',  -- ["kb_module_missing","raw_text_unparsed","vector_unavailable"...]
    participants        JSONB NOT NULL DEFAULT '[]',  -- ["chief:qwen-max","jury_a:deepseek-flash",...]

    -- 评审上下文（见 03 §1）
    test_scope          JSONB,                        -- {feature_point, required_scenarios, related_case_ids, scope_version}
    automation_context  JSONB,                        -- {framework, supported_operations, state_query_capabilities,
                                                     --  data_setup_capabilities, limitations}

    -- 版本
    kb_version          TEXT,
    rubric_version      TEXT,
    prompt_versions     JSONB,                        -- {"chief_blind":"p-1a2b", ...}
    prompt_version_hash TEXT NOT NULL,                -- sha256(prompt_versions) 前 12 位，供幂等索引
    retrieval_config_version TEXT,

    -- 输入与结果
    input_hash          TEXT NOT NULL,
    request_payload     JSONB NOT NULL,               -- 原始请求体
    normalized_case     JSONB,                        -- 规范化后的用例（含预处理拆分的 steps）
    report_summary      JSONB,                        -- 报告摘要
    error               TEXT,                         -- 失败原因（人类可读）

    -- 队列控制（持久化队列 / 租约 / 重试）
    attempt_count       INT  NOT NULL DEFAULT 0,
    max_attempts        INT  NOT NULL DEFAULT 3,
    locked_by           TEXT,                         -- worker 标识
    locked_at           TIMESTAMPTZ,
    lease_expires_at    TIMESTAMPTZ,                  -- 租约到期，过期可被其他 worker 领取
    last_error          TEXT,

    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    started_at          TIMESTAMPTZ,
    finished_at         TIMESTAMPTZ,

    UNIQUE (case_id, input_hash, kb_version, rubric_version, prompt_version_hash)
);

CREATE INDEX idx_review_jobs_case    ON review_jobs (case_id, created_at DESC);
CREATE INDEX idx_review_jobs_module  ON review_jobs (module, created_at DESC);
CREATE INDEX idx_review_jobs_verdict ON review_jobs (verdict, created_at DESC);
CREATE INDEX idx_review_jobs_batch   ON review_jobs (batch_id);

-- 队列领取：只扫可执行任务，避免全表扫描
CREATE INDEX idx_review_jobs_queue
    ON review_jobs (status, lease_expires_at, created_at)
    WHERE status IN ('queued', 'processing');

-- ───────────── 模型调用存档 ─────────────
CREATE TABLE model_runs (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    review_id         UUID NOT NULL REFERENCES review_jobs(id) ON DELETE CASCADE,
    role              TEXT NOT NULL,        -- chief_blind|jury_a|jury_b|vote|arbitration|preprocess
    provider          TEXT,                 -- qwen|deepseek|kimi
    model             TEXT NOT NULL,        -- 逻辑模型标识（配置项，如 qwen-max / deepseek-flash）
    requested_model   TEXT,                 -- 本次请求真正发出的 model 字段（厂商要求的 ID 或别名）
    model_version     TEXT,                 -- API 响应返回的版本（若有）
    prompt_version    TEXT,
    attempt           INT  NOT NULL DEFAULT 1,
    status            TEXT NOT NULL,        -- ok|timeout|error|parse_error
    request_tokens    INT,
    response_tokens   INT,
    latency_ms        INT,
    raw_request       JSONB,                -- 完整请求（含 messages），内部可读
    raw_response      JSONB,                -- 完整响应
    parsed_output     JSONB,                -- 解析后的结构化输出
    parse_warnings    JSONB NOT NULL DEFAULT '[]',
    error             TEXT,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_model_runs_review ON model_runs (review_id, role);

-- ───────────── 问题条目 ─────────────
CREATE TABLE issues (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    review_id       UUID NOT NULL REFERENCES review_jobs(id) ON DELETE CASCADE,
    issue_no        INT  NOT NULL,                    -- 报告内的 ISSUE-001 编号
    step_index      INT,                              -- null = 用例级
    step_tolerance  INT  NOT NULL DEFAULT 1,          -- 融合时的邻步容差
    dimension       TEXT NOT NULL,                    -- business|test_design|automation
    severity        TEXT NOT NULL,                    -- blocker|major|suggestion
    category        TEXT NOT NULL,
    evidence_quote  TEXT,
    rationale       TEXT NOT NULL,
    suggestion      TEXT,
    kb_grounded     BOOLEAN NOT NULL DEFAULT FALSE,
    kb_refs         JSONB NOT NULL DEFAULT '[]',      -- ["RULE-DIG-012","chunk:8842"]
    evidence_refs   JSONB NOT NULL DEFAULT '[]',      -- 证据包中的引用（含 source_ref / heading_path）
    proposed_by     JSONB NOT NULL DEFAULT '[]',      -- ["chief_blind","jury_a"]
    merged_from     JSONB NOT NULL DEFAULT '[]',      -- [{"reviewer":"jury_a","text":"原始问题摘要","step_index":3}]
    fusion_basis    JSONB,                            -- {"bucket":"...","max_cosine":0.93,"rerank_score":0.88,"rule":"same_root_cause"}

    -- 投票计数（冗余字段，便于统计与排序；明细见 issue_votes）
    support_count       INT NOT NULL DEFAULT 0,
    reject_count        INT NOT NULL DEFAULT 0,
    not_assessed_count  INT NOT NULL DEFAULT 0,
    uncertain_count     INT NOT NULL DEFAULT 0,
    support_ratio       NUMERIC(3,2),

    confidence          NUMERIC(3,2),                 -- 校准后才有值；未校准为 NULL
    confidence_source   TEXT NOT NULL DEFAULT 'uncalibrated', -- uncalibrated|calibrated

    status          TEXT NOT NULL,                    -- adopted|rejected|disputed|need_human|chief_supplement
    chief_decision  TEXT,                             -- adopt|reject|dispute|need_human|supplement
    chief_reason    TEXT,                             -- 驳回/补充理由，必填
    human_verdict   TEXT,                             -- adopt|reject|missed（复核回写）
    human_note      TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),

    UNIQUE (review_id, issue_no)
);

CREATE INDEX idx_issues_review   ON issues (review_id);
CREATE INDEX idx_issues_severity ON issues (severity, status);
CREATE INDEX idx_issues_human    ON issues (human_verdict);

-- ───────────── 每个模型对每个候选问题的态度 ─────────────
CREATE TABLE issue_votes (
    id                  BIGSERIAL PRIMARY KEY,
    issue_id            UUID NOT NULL REFERENCES issues(id) ON DELETE CASCADE,
    review_id           UUID NOT NULL,
    reviewer_id         TEXT NOT NULL,      -- 评审角色：chief_blind|jury_a|jury_b（与 model_runs.role=vote 的调用对应）
    vote                TEXT NOT NULL,      -- accept|reject|not_assessed|uncertain
    reason              TEXT,
    evidence_refs       JSONB NOT NULL DEFAULT '[]',
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),

    UNIQUE (issue_id, reviewer_id)
);

CREATE INDEX idx_issue_votes_review ON issue_votes (review_id, vote);

-- ───────────── Embedding Profile（向量由谁生成） ─────────────
CREATE TABLE embedding_profiles (
    id              BIGSERIAL PRIMARY KEY,
    provider        TEXT NOT NULL,          -- qwen|local
    model           TEXT NOT NULL,
    model_version   TEXT,
    dimension       INT  NOT NULL,
    similarity_metric TEXT NOT NULL DEFAULT 'cosine',
    normalize       BOOLEAN NOT NULL DEFAULT TRUE,
    config_version  TEXT NOT NULL,
    status          TEXT NOT NULL DEFAULT 'active',  -- active|candidate|retired
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),

    UNIQUE (provider, model, model_version, dimension, config_version)
);

-- ───────────── 问题向量（用于同义合并与历史检索） ─────────────
CREATE TABLE issue_embeddings (
    issue_id             UUID PRIMARY KEY REFERENCES issues(id) ON DELETE CASCADE,
    review_id            UUID NOT NULL,
    content              TEXT NOT NULL,           -- 用于生成向量的文本（rationale + evidence_quote）
    embedding_profile_id BIGINT NOT NULL REFERENCES embedding_profiles(id),
    embedding            vector(1024) NOT NULL    -- 维度与 profile 绑定；换维度需迁移
);

CREATE INDEX idx_issue_embeddings_ivf
    ON issue_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

-- ───────────── 人工复核回写 ─────────────
CREATE TABLE human_feedback (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    review_id       UUID NOT NULL REFERENCES review_jobs(id) ON DELETE CASCADE,
    issue_id        UUID REFERENCES issues(id),     -- null = 针对整份报告的结论
    verdict         TEXT NOT NULL,                 -- adopted|rejected|missed
    note            TEXT,
    reviewer        TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_human_feedback_review ON human_feedback (review_id);

-- ───────────── 知识库文档 ─────────────
CREATE TABLE kb_documents (
    id              BIGSERIAL PRIMARY KEY,
    module          TEXT NOT NULL,
    doc_id          TEXT NOT NULL,
    title           TEXT NOT NULL,
    content         TEXT NOT NULL,
    doc_type        TEXT NOT NULL,                 -- requirement|design|gm_command|known_limit|history_bug|term
    source_ref      TEXT,                          -- 原始出处（文档名/章节）
    kb_version      TEXT NOT NULL,
    UNIQUE (doc_id, kb_version)
);

CREATE INDEX idx_kb_documents_module ON kb_documents (module, doc_type);

CREATE TABLE kb_rules (
    id              BIGSERIAL PRIMARY KEY,
    rule_id         TEXT NOT NULL,                 -- RULE-DIG-012
    module          TEXT NOT NULL,
    function_point  TEXT NOT NULL,
    rule_text       TEXT NOT NULL,
    source_ref      TEXT,
    kb_version      TEXT NOT NULL,
    UNIQUE (rule_id, kb_version)
);

CREATE INDEX idx_kb_rules_module ON kb_rules (module, function_point);

-- ───────────── 知识切片（must 可溯源） ─────────────
CREATE TABLE kb_chunks (
    id                   BIGSERIAL PRIMARY KEY,
    doc_id               TEXT NOT NULL,
    module               TEXT NOT NULL,
    function_point       TEXT,                     -- 关联具体功能点
    doc_type             TEXT NOT NULL,            -- rule|requirement|known_limit|history_bug|term|flow
    chunk_index          INT  NOT NULL,            -- 切片在原文中的顺序
    heading_path         TEXT,                     -- Markdown 标题层级路径
    content              TEXT NOT NULL,
    source_ref           TEXT,                     -- 原始文档 + 章节/行号
    content_hash         TEXT NOT NULL,            -- 判断内容是否变化，支撑增量更新
    token_count          INT,                      -- 估算注入预算
    embedding_profile_id BIGINT REFERENCES embedding_profiles(id),
    embedding            vector(1024),
    kb_version           TEXT NOT NULL,

    -- 关键词检索（中文需 zhparser，配置名 zh；未安装则 simple 仅对 ASCII/数字有效）
    search_vector        tsvector GENERATED ALWAYS AS (to_tsvector('simple', content)) STORED,

    UNIQUE (doc_id, chunk_index, kb_version)
);

CREATE INDEX idx_kb_chunks_ivf
    ON kb_chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
CREATE INDEX idx_kb_chunks_fts     ON kb_chunks USING gin (search_vector);
CREATE INDEX idx_kb_chunks_filter  ON kb_chunks (module, function_point, doc_type, kb_version);
CREATE INDEX idx_kb_chunks_profile ON kb_chunks (embedding_profile_id);

-- ───────────── 知识库缺口 ─────────────
CREATE TABLE kb_gaps (
    id              BIGSERIAL PRIMARY KEY,
    module          TEXT,
    function_point  TEXT,
    suspected_rule  TEXT NOT NULL,                 -- 被反复判断但知识库里找不到依据的规则
    examples        JSONB NOT NULL DEFAULT '[]',   -- 关联的 issue 文本样例
    occurrences     INT  NOT NULL DEFAULT 1,
    first_seen      TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_seen       TIMESTAMPTZ NOT NULL DEFAULT now(),
    status          TEXT NOT NULL DEFAULT 'open',  -- open|accepted|dismissed|merged
    handled_by      TEXT,
    handled_at      TIMESTAMPTZ
);

CREATE INDEX idx_kb_gaps_status ON kb_gaps (status, occurrences DESC);
```

## 3. 关键设计说明

1. **`review_jobs` 的唯一约束是幂等键**：同用例、同输入、同知识库、同 rubric、同 prompt 版本不会重复评审；要复跑必须带 `force=true`，此时插入新记录（旧记录保留，形成天然的历史对比）。`prompt_versions` 是 JSONB，不能直接进复合唯一索引，因此另存 `prompt_version_hash`。
2. **`review_jobs` 同时是任务队列**：`status + lease_expires_at` 支撑 `FOR UPDATE SKIP LOCKED` 领取与崩溃恢复，进程重启不丢任务；队列索引带部分条件，避免扫历史数据。
3. **`model_runs` 存全量原文**：这是复盘、调优、黄金集标注的唯一依据，比只存解析后结果重要得多；`requested_model` 与 `model_version` 分开，用于发现"配置别名"与"厂商实际版本"的偏差。
4. **投票明细与计数分离**：`issue_votes` 是审计事实（每个模型一个态度），`issues.support_count` 等是冗余计数，便于统计与排序；两者由同一事务写入。
5. **融合必须留痕**：`merged_from` 记录被合并的原始问题，`fusion_basis` 记录分桶键、最高余弦、rerank 分数与判定规则；否则无法排查"错误合并/重复报告/漏报"的来源。
6. **`not_assessed` 必须落库**：未提及不等于反对，如果只存"支持/反对"，就无法区分"两方反对"与"一方反对、一方没说话"。
7. **置信度允许为空**：未做黄金集校准前 `confidence=NULL`、`confidence_source=uncalibrated`，报告展示 `support_ratio` 与计数，不伪造小数点。
8. **`issues` 用 `issue_no` 对外展示**：报告里 `ISSUE-001` 可读、可引用、稳定。
9. **`evidence_refs` 与 `kb_refs` 分工**：`kb_refs` 供人读（RULE-ID），`evidence_refs` 供机器追溯（chunk_id、source_ref、检索通道、rerank 分数）。
10. **知识库按 `kb_version` 快照存储**：不覆盖历史版本，报告引用的 `kb_refs` 永远能回查到当时的规则原文。
11. **`kb_chunks` 的溯源字段是硬要求**：切片后不能只剩正文——规则 ID、适用范围、前置条件、原文位置必须绑在同一行，否则报告无法证明"依据在哪"。
12. **切片粒度按知识类型**：一条规则 / 一个功能点 / 一条已知限制 / 一个历史缺陷 / 一个术语 / 一个完整流程，各自一个 chunk；不按固定字符数硬切。
13. **Embedding 换模型 = 新 profile + 新索引**：`embedding_profile_id` 让每个向量都能回答"谁生成的"；混用不同模型的向量会让相似度失去意义，重建并评测后才切换。
14. **`human_verdict` 与 `human_feedback` 双写**：`issues.human_verdict` 是便捷冗余字段，便于统计；`human_feedback` 是审计流水。
15. **`kb_gaps` 是知识库的生长机制**：`occurrences` 排序即可看出优先该补哪些规则。
