## 3. 关键实现要点

### 3.1 结论由服务端计算

`verdict.py` 是唯一权威。模型输出 `verdict` 只作为对照，不一致时记日志并用服务端结果覆盖。这是防止仲裁模型"凭感觉给结论"的最后一道闸。

### 3.2 仲裁输出完整性校验

仲裁返回后，服务端逐条比对候选清单：

```
缺失条目 → 补为 need_human，parse_warnings += "arbitration_omitted:FUSED-00X"
出现清单外条目 → 若 chief_decision=supplement 且证据完整则接受；否则丢弃并记警告
chief_decision=reject 但未填 chief_reason → 视为无效，补 need_human
```

投票完整性同理：投票轮缺失的候选补 `not_assessed`，并在报告中标注投票不完整。

### 3.3 检索与向量

- **Embedding 必须带 profile**：`build_kb_index.py` 首次运行创建 `embedding_profiles` 记录；换模型/维度 = 新 profile + 新索引，旧索引保留到评测完成。
- **不混用向量**：同一查询只能与同 profile 的向量比较；`issue_embeddings` 与 `kb_chunks` 都记录 `embedding_profile_id`。
- **融合中的 embedding 调用**：用同一 profile 生成问题文本向量；若 embedding 服务不可用，退化为规则键直接合并，并在报告标注"本次融合未使用语义合并"。
- **检索降级**：向量不可用 → 过滤 + FTS；FTS 不可用 → 纯向量；rerank 超时 → 用 RRF 排序；全部写入 `degraded_reasons`。
- **检索参数版本化**：`RETRIEVAL_CONFIG_VERSION` 由 Top-K、RRF k、rerank 阈值、查询上限等参数哈希生成，写入报告；参数变更触发检索回归。

### 3.4 队列与状态推进

- **PostgreSQL 持久化队列**：任务创建即落库（`status=queued`），worker 用 `FOR UPDATE SKIP LOCKED` 领取，不依赖进程内存。
- **租约机制**：领取写 `locked_by/locked_at/lease_expires_at`，执行期按 `QUEUE_LEASE_SECONDS/3` 续租；worker 崩溃后租约过期，任务自动回到可领取状态。
- **重试**：失败按退避重试，`attempt_count` 超过 `QUEUE_MAX_ATTEMPTS` 置 `failed` 并记 `last_error`。
- **状态实时写库**：每个 stage 变更更新 `review_jobs.stage`；进程重启不丢任务，也不需要"重启后重置 processing"的特殊逻辑（租约过期即恢复）。
- **终稿幂等**：写入终稿前校验 `status` 与 `attempt`，同一任务重复执行不得产生两份冲突报告。
- 批量任务只是 `review_jobs.batch_id` 的聚合，不单独调度。

### 3.5 版本号

```python
kb_version              = sha256(所有 kb_content 文件内容 + 规则文件) 取前 12 位
rubric_version          = sha256(rubric.yaml) 取前 12 位
prompt_version          = 每个 prompt 文件独立 sha256 前 8 位（含 vote.jinja2）
retrieval_config_version= sha256(检索参数 JSON) 取前 8 位
```

版本号在服务启动时计算并缓存；知识库热重载后重新计算。`model_versions` 同时记录配置值与 API 实际返回的版本。

## 5. 开发顺序（里程碑）

| 里程碑 | 内容 | 完成标志 |
|---|---|---|
| M0 | 骨架：FastAPI + DB + 模型 Mock + 结论判定 | `seed_demo.py` 用 mock 输出跑通全链路，报告可渲染 |
| M1 | 持久化队列 + 真实三模型接入 + 存档 + 计量 | 杀死进程后任务能被重新领取；单份用例得到真实报告 |
| M2 | 知识库加载 + 按类型切片 + 检索黄金集 | 检索评测脚本可跑，输出 Recall/MRR/nDCG |
| M3 | Hybrid 检索 + rerank + 证据包 + 降级 | 模块命中/未命中/通道降级三条路径都可复现，证据可溯源 |
| M4 | 融合 + 投票轮 + 仲裁校验 + 人工复核清单 | 同一问题多模型提出时正确合并；投票完整；驳回项进清单 |
| M5 | 复核回写 + 缺口聚合 + 批量接口 | 复核能落库，缺口清单可导出 |
| M6 | 评审黄金集评测 + 阈值与 prompt 调优 | 指标达标（见 07），检索与评审指标分开报告 |

> M0–M5 完成后再做端到端演示，M6 才动 prompt 细节 —— 没有评测数据前调 prompt 是盲调。
