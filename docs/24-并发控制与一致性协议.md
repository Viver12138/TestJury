# 24 · 并发控制与一致性协议

> 版本：v1.1 · 2026-11-10（冻结修订）
> 目的：定义租约栅栏、重复执行、投票重试、批量幂等与终稿写入的并发协议。
> 关联：02、13、14、22。

---

## 1. 租约与 fencing token

在 `locked_by`/`attempt` 之外增加单调递增的 `fencing_token`：

1. **仅在所有权转移时递增**：首次领取或新 Worker 接管过期任务时 `fencing_token += 1`（数据库原子 `UPDATE ... RETURNING`）；当前 Worker 正常续租**不递增**。
   - 反例：续租也递增会导致 Worker 尚未完成的写入携带旧令牌被拒，误伤合法执行者。
2. Worker 持有本次令牌；所有阶段结果、投票、终稿写入必须携带该令牌。
3. 写入条件：`WHERE id=:review AND fencing_token=:token AND status IN (...)`；影响行数为 0 即失去执行权，立即停止。
4. 旧 Worker 恢复后令牌已过期，其写入被数据库拒绝；不得覆盖新 Worker 结果。
5. 令牌校验必须在 SQL 事务内完成，不能只在应用层先查后写。

## 2. 租约过期接管

| 步骤 | 动作 |
|---|---|
| 1 | Worker B 领取租约过期任务，`fencing_token+1` |
| 2 | B 读取最后成功阶段，校验 `input_digest` 与冻结版本 |
| 3 | A 恢复后写入被令牌拒绝，A 记录 `fenced_out` 并退出 |
| 4 | B 完成或失败；终稿仅允许一个令牌写入 |

同一任务任意时刻最多一个有效令牌；`processing` 状态的租约续期失败即视为失去执行权。

## 3. 阶段与投票重试

- 阶段重试写新的 `review_stage_attempts`（`attempt_no` 递增、带令牌），不覆盖历史。
- 投票重试生成新的 `model_runs`，但 `issue_votes` 仍 `UNIQUE(candidate_id, reviewer_id)`：
  - 首次成功投票为准；
  - 失败/非法输出不写票；
  - 若首次未成功，重试成功票生效；
  - 不允许同一候选同一模型存在两套有效票。
- 需要保留每次投票尝试时，历史在 `model_runs` 与 attempt 表，不在 `issue_votes` 里堆多行。

## 4. 批量幂等

- 批次级：`batches.idempotency_key`（用例集合 + 配置版本）唯一；重复提交未 `force` 返回原批次。
- 子任务级：仍用单条 `idempotency_key`；成功子任务保留结果。
- `force=true` 默认只重跑失败/未完成子任务；`force_all=true` 才整批重跑。
- 用例内容变化只影响对应子任务，其他子任务不重跑。
- 批次状态由子任务聚合，不单独维护"完成"事实。

## 5. 终稿写入

同一事务内：

1. 校验 `fencing_token`、`status`、`generation`；
2. 写 `report_json`、`issues` 投影、`report_locked_at`；
3. 更新 `review_jobs.status/ai_verdict`；
4. 写 `review_stages(render)`。

任一步失败整体回滚；已存在终稿则拒绝第二次写入。

## 6. 隔离级别

- 默认 `READ COMMITTED`；领取任务用 `FOR UPDATE SKIP LOCKED`。
- 终稿与审批事务使用行锁（`SELECT ... FOR UPDATE`）。
- 不使用长事务跨模型调用；模型调用在事务外，结果写入短事务。
