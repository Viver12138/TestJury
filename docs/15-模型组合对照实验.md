# 15 · 模型组合对照实验

> 版本：v1.6 · 2026-11-10（补充 15 落实：指标口径与阈值冻结、第三模型判定问题）
> 目的：证明"多模型评审团"相对单模型/同模型重复采样是否真的产生价值，而不是只增加成本。
> 关联：07 §3、12。

---

## 1. 实验组

生产拓扑不预先写死：实现支持 `single` / `dual` / `multi`，由本实验决定默认值；角色与 Prompt 可先冻结，拓扑由结果决定。

- `single` 仅作为 A 组实验基线，**不允许生成正式完整评审结论**。
- 正式生产至少 `dual`（主审 + 1 陪审）。
- 所有拓扑使用同一套真值表；2 人时需 2 票一致（见 `docs/12`）。
- 报告必须记录 `topology`、实际参与模型、角色与缺席原因。

| 组 | 组合 | 目的 |
|---|---|---|
| A | 仅 Qwen 主审 | 单模型基线 |
| B | Qwen + DeepSeek | 两模型增量 |
| C | Qwen + Kimi | 两模型增量（不同视角） |
| D | Qwen + DeepSeek + Kimi | 完整评审团 |
| E | Qwen 独立调用 3 次（同模型） | 区分"多次采样"与"模型差异" |

可选：

| 组 | 组合 | 目的 |
|---|---|---|
| F | Qwen + DeepSeek + Kimi，但隐藏投票来源 | 验证防锚定是否有效 |
| G | 单模型 + 规则融合（无投票） | 验证投票机制本身的增量 |

## 2. 控制条件

- 同一冻结评测集（`frozen`），不得用于调参。
- 同一输入、同一 Rubric 版本、同一 Prompt 版本、同一知识库版本。
- 记录每个模型的真实 Model ID、返回版本、参数、超时/重试配置。
- 同一预算上限；成本单独统计。
- **等预算/等成本对照**：除 A–E 原始组外，增加"总 token 预算相同"与"总调用成本相同"的对照，避免多模型收益只是花了更多钱。
- **错误重合分析**：记录各模型独立发现的问题、重合与差异，计算 Error Overlap 与 Incremental Valid Issue Rate。
- 评测集不得泄漏进 Prompt 或知识库。
- 每组样本量一致；随机顺序执行，避免时段偏差。

### 2.1 实验协议冻结清单

实验开始前必须把下列 12 项写入 `data/experiments/protocol-<date>.yaml`，由实验负责人与评审负责人共同签署。**未签署不得启动正式实验；中途变更任一项，该组结果作废重跑**；探索性变更单独标注，不进入主分析。

| # | 冻结项 | 冻结内容（写入协议文件） | 证据/字段 |
|---|---|---|---|
| 1 | 组定义 | A–E 各自拓扑、角色、参与者数；single 仅实验 | `group`/`topology`/`participants` |
| 2 | 样本集与分层 | `frozen` 集版本；按模块、风险级、复杂度、缺陷类别分层 | `dataset_version`/`strata` |
| 3 | 样本分配 | 同一用例跑全部组（配对）；每组样本量一致 | `case_id` 配对表 |
| 4 | 模型与参数 | `models.yaml` 版本、真实 Model ID、temperature、max_tokens、超时/重试 | `model_config_version`/`real_model_id` |
| 5 | Prompt/Rubric/KB | 三者版本号；实验期间锁定 | `prompt_version`/`rubric_version`/`kb_version` |
| 6 | 随机化与顺序 | 执行顺序随机种子；并发上限；时段 | `random_seed`/`concurrency` |
| 7 | 重复次数 | 每用例每组运行次数；取多次结果的规则 | `repeats`/`aggregation` |
| 8 | 失败与重试统计 | 失败/超时/重试样本是否计入分母；丢弃规则 | `failure_policy` |
| 9 | 人工盲评流程 | 标注者数量、盲评材料、是否见组别 | `annotators`/`blind` |
| 10 | 标注分歧处理 | 双人标注 + 第三人裁决；一致性指标与报告方式 | `adjudication`/`kappa` |
| 11 | 成本口径 | Token 与价格版本；失败/重试调用是否计入；缓存命中处理 | `price_config_version`/`cost_basis` |
| 12 | 默认拓扑批准条件 | D vs A 的显著性门槛、置信区间下界、成本上限、可维护性否决项 | `approval_rule` |

**人工标注一致性**：两名标注者用 Cohen's κ，多名用 Fleiss' κ（或与标注结构匹配的指标）；必须同时报告样本分布、类别比例、严重级有序性对指标的影响，不能只报一个 κ 数值。κ 低于预设阈值（建议 0.6）时先校准标注口径，不得直接进入主分析。

**协议变更记录**：每次变更写 `protocol_changes[]`（时间、字段、原因、影响组、是否重跑）；未记录的变更视为实验缺陷。

### 2.2 指标定义与阈值冻结

指标必须与协议一起冻结，避免实验后"换口径"：

| 指标 | 定义/公式 | 分母 | 统计单位 |
|---|---|---|---|
| Strict Blocker Recall | 真实 blocker 中被报告为 blocker 且语义对齐的比例 | 人工 blocker 数 | Case / Issue |
| High-risk Recall | 人工 blocker+major 中被报告为 blocker/major 的比例 | 人工 blocker+major 数 | Case / Issue |
| FDR | 报告采用问题中人工判 rejected 的比例 | 报告采用问题数（TP+FP） | Issue |
| Incremental Valid Issue Gain | 新增模型发现且人工确认成立的问题数 / 原模型确认问题数 | 原模型确认问题数 | Issue |
| Cost per Valid Issue | 总成本 / 人工确认成立的问题数 | 有效问题数 | Run |
| Latency | P50/P95 端到端（不含排队） | 运行次数 | Run |
| Failure Rate | 失败/超时/非法输出运行数 / 总运行数 | 总运行数 | Run |

- 每个指标的门槛、方向（越高/越低越好）与可接受波动在协议签署前写入，实验中途不得修改。
- 报告点估计、95% 置信区间与分层结果（模块/复杂度/风险级）；样本不足必须标"探索性"。
- 失败/超时/重试统一计入分母，或按协议显式排除并说明；不得只统计成功样本。
- **第三模型问题**不是"能否发现更多问题"，而是："在增加的成本与延迟下，第三个模型是否稳定带来足够多的新增有效问题且不显著增加误报？"

## 3. 指标

| 指标 | 定义 | 关注 |
|---|---|---|
| Strict Blocker Recall | 真实 blocker 被判为 blocker 的比例 | 越高越好 |
| High-risk Recall | 真实 blocker+major 被判为 blocker 或 major 的比例 | 越高越好 |
| Blocker Detection Recall | 真实 blocker 被判为 blocker 或 major 的比例（辅助） | 越高越好 |
| False Discovery Rate (FDR) | 报告采用的问题中人工判 rejected 的比例 | 越低越好 |
| False Negative Rate | 真实问题未被报告覆盖的比例 | 越低越好 |
| Severity Accuracy | accepted 问题中严重级与人工一致的比例 | 越高越好 |
| Human Review Rate | 进入人工复核的比例 | 越低越好（但不能牺牲召回） |
| Cost per Case | 单条评审总成本 | 越低越好 |
| Cost per Valid Issue | 总成本 / 人工确认成立的问题数（定义见 `docs/07` §3.9） | 越低越好 |
| Review Latency | P50/P95 端到端 | 越低越好 |
| Run-to-Run Stability | 同一输入重复运行的结论一致率与指标波动 | 波动越小越可信 |
| Evidence Accuracy | 证据与 claim 匹配的比例 | 越高越好 |
| Incremental Valid Issue Rate | 新增模型发现、原模型未发现且人工确认成立的问题比例 | 越高越好 |
| Incremental Valid Issue Gain | 新增模型发现且人工确认成立的问题数 / 原模型确认问题数（`docs/07` §3.9） | 越高越好 |
| Error Overlap Rate | 各模型错误（误报/漏报）重合比例 | 越低越说明互补 |

## 4. 分析

- 主分析：D vs A（多模型总收益）、B/C vs A（单模型增量）、E vs A（重复采样收益）。
- 报告效应量（差值 + 置信区间），不只报均值。
- 分层看：blocker / major / suggestion；模块；证据充分/缺失。
- 成本-收益：每提升 1 个百分点的召回增加多少成本。
- 结论必须能回答："多模型是否值得"以及"收益来自模型差异还是重复采样"。

### 4.1 统计可靠性

- **样本量**：正式实验前用功效分析估算；每个比较组至少覆盖足够的 blocker 样本（建议 ≥ 50 个真实 blocker 事件），不足时只报告探索性结论。
- **配对比较**：同一用例在同一评测集上跑 A/D，按用例配对比较，不用独立样本均值。
- **区间**：报告点估计 + 95% 置信区间（bootstrap 或配对检验）。
- **显著性**：预先声明检验方法与阈值；多重比较需校正。
- **分层**：按风险等级、模块、证据充分性分层报告，避免总体均值掩盖局部退化。
- **模型更新**：模型版本变化后重新实验，不与旧版本结果直接混算。

> 如果 D 相对 A 只提升 2% 且置信区间跨 0，不得据此把三模型设为默认生产架构。

## 5. 记录模板

每次实验产出一份 `data/experiments/<日期>-<组>.json`：

```json
{
  "group": "D",
  "models": { "chief": "qwen-max", "jury_a": "deepseek-chat", "jury_b": "kimi-k3" },
  "versions": { "prompt": "...", "rubric": "...", "kb": "..." },
  "dataset": "frozen-2026-11",
  "metrics": { "strict_blocker_recall": 0.0, "high_risk_recall": 0.0, "fdr": 0.0, "cost_per_case": 0.0 },
  "notes": "结论与异常"
}
```

## 6. 判定

- 若 D 相对 A 没有显著提升（召回/误报），不增加模型数量，先修 Prompt/Rubric/检索。
- 若 E 与 D 接近，说明收益主要来自重复采样，可考虑同模型多次调用替代多模型（成本更低）。
- 若 D 提升但成本不可接受，按模块/风险分级启用多模型。
- 未完成对照实验前，不得宣称"评审团优于单模型"。
- **架构决策门槛**：D vs A 的 Strict Blocker Recall/Blocker Precision 没有统计显著提升时，不把"完整三模型"作为固定生产架构；角色可先冻结，组合由实验结果决定（见 README 决策 90）。
