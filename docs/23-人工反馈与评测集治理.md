# 23 · 人工反馈与评测集治理

> 版本：v1.3 · 2026-11-10（M0 前契约收口）
> 目的：规范人工反馈如何进入评测集，避免普通反馈直接改规则、污染评测基线。
> 关联：07、09、16、21。

---

## 1. 反馈类型

| 类型 | 来源 | 用途 |
|---|---|---|
| issue 级反馈 | `human_feedback` | 误报/漏报/采纳，评测信号 |
| 报告级决定 | `review_decisions` | 业务审批，不改规则 |
| 知识缺口 | `kb_gaps` | 知识库补充候选 |
| 人工修正 | 反馈 + 说明 | 候选评测样本 |

**普通反馈不得直接修改 Rubric、Prompt 或生产规则。**

## 2. 进入评测集的流程

```
人工反馈
  → 待审核样本池（pending）
  → 第二人复核（同意/驳回/需补充）
  → 通过：进入 candidate 集
  → 冻结：进入 formal 评测集（带版本）
  → 定期重跑基线
```

**追溯链**必须可从任一环查到下一环：

`review_id → issue_id → human_feedback_id → evaluation_sample_id → evaluation_dataset_version`

- 每条样本记录来源反馈 ID、审核人、批准时间、入集版本；
- 撤销/修正保留历史，不覆盖原样本；
- 用于调参/Prompt 优化的样本不得未经隔离进入正式验收集。

- 每条样本记录：来源 `review_id`、原始 AI 结论、人工修正、理由、标注人、复核人、时间、适用版本。
- 未复核的反馈只能用于观察，不能进入正式指标。
- 驳回的反馈保留记录，不删除。

## 3. 样本质量要求

| 项 | 要求 |
|---|---|
| 来源 | 必须能追溯到具体评审与 issue |
| 盲标 | 标注时不得看模型输出（除已判定的对照） |
| 双人 | 关键样本第二人复核；分歧第三人裁决 |
| 版本 | 标注标准版本、KB 版本、Prompt 版本 |
| 适用性 | 标明适用的产品版本/模块 |
| 一致性 | 定期计算标注一致率（κ/α） |

## 4. 评测集版本

- `eval-<date>-<n>`：每次冻结生成新版本，不覆盖旧版本。
- 指标报告必须写清数据集版本。
- 数据集变更后，需重跑基线与当前版本，不能只跑新样本。
- 冻结集不得用于调参；调参用 dev/validation。

## 5. 防止污染

- 人工反馈不得自动成为"正确答案"；必须复核。
- 不允许把模型输出当标注。
- 不允许把评测样本写入 Prompt 或知识库。
- 发现数据集泄漏 → 立即冻结该版本，重新构建。

## 6. 与发布门禁的关系

- `docs/21` 的指标必须基于 formal 评测集。
- 人工反馈池中未复核样本不计入发布指标。
- 数据集版本变化时，发布门禁需重新计算并记录差异。
