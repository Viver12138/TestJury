# 10 · 安全与可靠性设计

> 版本：v1.6 · 2026-11-10（补充 15 落实：身份分层、供应商数据准入、附件定位）
> 范围：鉴权、密钥、数据与隐私、Webhook、模型调用可靠性、任务恢复、降级、成本预算、审计与保留。
> 关联：01 §8/§9、02 §2、03 §1/§4、06 §2、09 §9、11 §7。

---

## 1. 原则

1. **失败必须显式**：任何降级、重试、超时都要写进报告与日志，不能静默修补成"正常完成"。
2. **最小暴露**：API Key、原始 Prompt、模型响应、用例内容按需可见，默认不对外。
3. **可恢复**：进程/Worker 崩溃后任务能恢复，且不产生重复终稿。
4. **可审计**：审批、强制重跑、配置变更、知识库发布全部留痕。
5. **成本可观测**：每次调用记录 token 与成本，超预算可中止或降级。

## 2. 鉴权与授权

| 项 | 规则 |
|---|---|
| 服务鉴权 | 请求头 `X-API-Key`；Key 按调用方分发，不共享 |
| 调用方标识 | `X-Caller-Id`，写入日志与报告 |
| 角色来源 | **服务端按 API Key 查授权表**；客户端 `X-Role` 不作为授权依据，只记日志 |
| 角色 | 全局角色与权限矩阵见 `docs/17` §5；`reviewer` / `approver` / `admin` 不可互相自动继承 |
| 管理接口 | 模型配置、账号权限、强制重跑仅 `admin`；知识库发布/回滚仅 `kb_publisher`（`admin` 不自动拥有） |
| 审批接口 | `approve` / `reject` 仅 `approver`，且审批人 ≠ 用例提交人（可配置放宽） |
| 失败响应 | 401/403，不返回内部配置、Key 片段或堆栈 |

**Key 生命周期**：按人/系统发放、绑定角色与有效期、定期轮换、可立即撤销；审批接口不接受共用 Key（见 `docs/09` §6.1）。

**身份分层**（补充 15 P0-6）：

| 身份 | 凭据 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 服务身份 `actor_type=service` | 系统 API Key / OIDC client credentials | 提交评审、查询结果、接收回调 | 审批、发布知识库、改权限 |
| 个人身份 `actor_type=human` | 个人 OIDC/SSO 或绑定个人的 Key | 复核、审批、反馈 | 共用、代他人审批（v1） |
| 管理员 `admin` | 个人身份 + 管理角色 | 系统配置、模型配置 | 不自动获得 `approver`/`kb_publisher` |

- 审批记录必须写 `actor_id` + `actor_type` + 认证来源 + request_id；系统 Key 调用审批返回 403。
- 人员离职/权限变更：IdP 禁用后令牌 ≤5 分钟失效；Key 撤销立即生效；未完成任务转派。
- 未来如支持代操作，必须记录 `actor_id`、`on_behalf_of` 与理由，不得静默代理。

> v1 是内部服务，但角色校验不能省：审批与知识库发布是高风险操作。

## 3. 密钥与配置管理

- API Key、数据库密码、供应商 Key 只从环境变量/密钥管理读取，**不写入** `.env.example`、代码、日志、报告。
- 日志脱敏：`Authorization`、`X-API-Key`、供应商 Key、数据库 URL 中的密码统一打码。
- 模型配置（`models.yaml`）可入库/入 Git，但其中只允许出现环境变量名，不出现明文 Key。
- 配置变更记录 `config_version` 与操作人，变更后需回归（见 `docs/07`）。

## 4. 输入数据与隐私

### 4.1 数据分级

| 级别 | 内容 | 处理 |
|---|---|---|
| 公开 | 模块名、功能点名 | 可正常记录 |
| 内部 | 用例标题、步骤、预期、测试数据 | 仅内部可见；发往外部模型前评估 |
| 敏感 | 真实用户数据、账号、手机号、订单号、内部地址 | 必须脱敏或禁止外发 |

### 4.2 外发策略

- 默认只发送用例文本与知识库证据，不发送调用方标识、内部文档路径以外的元数据。
- 若用例可能包含真实用户数据，调用方需先脱敏；服务端提供可配置的正则脱敏（手机号、身份证、邮箱、IP）。
- 在报告与日志中保留"已脱敏"标记，避免误以为原始数据被完整评审。

**供应商级数据政策**（接入前逐家确认并记录）：

| 项 | 需确认 |
|---|---|
| 数据保留 | 供应商是否留存请求/响应、保留多久 |
| 训练使用 | 是否用于模型训练，能否关闭 |
| 存储区域 | 数据驻留国家/区域 |
| 日志 | 供应商侧日志内容与保留期 |
| 企业协议 | 是否可签 DPA/隐私协议 |
| 跨供应商 | 同一数据是否会被转发给其他供应商 |

不同供应商可能不同，不能写一条"按合规要求"就带过；政策变化时更新配置并重跑合规评审。

**供应商数据准入状态**（补充 15 P1）：技术上可调用 ≠ 业务上允许外发。模型注册表必须记录：

| 字段 | 取值/含义 |
|---|---|
| `data_admission_status` | `pending` / `approved` / `approved_with_masking` / `rejected` |
| `allowed_data_level` | 允许发送的最高等级（`public`/`internal`/`sensitive`） |
| `allow_raw_case` | 是否允许发送原始用例正文（false 时必须脱敏后再发） |
| `requires_masking` | 发送前是否强制脱敏 |
| `training_use` | 是否用于训练（`no`/`opt_out`/`yes`） |
| `retention_policy` | 供应商保留期限与删除方式 |
| `processing_region` | 数据处理区域 |
| `vendor_log_access` | 供应商运维人员访问权限说明 |
| `dpa_signed` | 是否签署企业协议/DPA |
| `last_audited_at` / `auditor` | 最近审核时间与责任人 |

规则：

- `data_admission_status != approved/approved_with_masking` 的模型**不得进入生产拓扑**，也不得用于正式评审（即使 `verification_status=verified`）。
- 发送前按 `allowed_data_level` 与 `requires_masking` 校验；等级超限直接拒绝，不静默发送。
- 供应商发生数据安全事件或政策变化 → 立即置 `pending`，暂停调用并重跑合规评审。
- 数据删除按 §4.4 覆盖供应商侧；删除动作与回执写入审计。

### 4.3 保留与删除

**数据生命周期表**（期限以公司政策/合同/法规为准，技术文档只给默认值）：

| 数据 | 存储位置 | 访问权限 | 默认保留 | 删除方式 | 验证 |
|---|---|---|---|---|---|
| 原始用例 | DB | 按评审授权 | 与报告一致 | 级联删除/归档 | 删除任务记录 |
| 模型请求/响应 | DB/归档 | admin/审计 | 180 天 | 到期删除 | 定期核验 |
| 评审报告 | DB | 按评审授权 | 长期 | 审批删除 | 审计记录 |
| 附件 | 本地卷 | 按评审授权 | 随评审 | 异步清理对象 + 记录 | 文件不存在校验 |
| 审计日志 | DB/归档 | 管理员只读 | ≥1 年 | 按制度 | 审计核验 |
| 数据库备份 | 独立存储 | 管理员 | 滚动周期 | 到期销毁 | 备份生命周期记录 |

> 本地删除 ≠ 生命周期结束：已发送给供应商的数据需按各家政策确认删除/保留；备份与 WAL 需按同一周期处理。

删除接口按 `review_id` 级联，审计日志只保留最小字段（见 `docs/09` §11）。

### 4.4 保留与删除的执行机制

只写期限不写执行机制等于没有策略：

| 项 | 规则 |
|---|---|
| 责任方 | 运维负责定期任务；数据负责人审批例外 |
| 执行方式 | 每日定时任务清理到期 `model_runs.raw_*`；报告与审批不自动删 |
| 按调用方删除 | 支持；需 `admin` 审批并写审计日志，先确认无未结审批 |
| 级联范围 | 删除评审任务 → 级联删除 `issues`/`issue_votes`/`candidates`/`decisions`/`webhook_deliveries`；审计保留最小字段 |
| 备份过期 | 备份按同周期滚动；恢复演练时不得把已删除数据重新带回生产查询 |
| 删除审计 | 记录操作人、范围、时间、理由；不可删除审计本身 |
| 合规配置 | 保留期限按法规/合同配置，不写死在代码 |

模型原始响应可能含用例内部信息，必须能按 `review_id` 或调用方定位并删除。

**附件删除与历史报告**：删除附件后，历史报告保留引用元数据（`attachment_id`/`sha256`），但不得再可下载；报告展示"附件已删除"。物理文件由异步清理任务删除，数据库记录标记 `status=deleted`，两者不一致时以清理任务重试收敛。删除评审任务时先标记，再异步清理，避免长事务。删除评审记录不级联物理删除附件，必须先完成附件软删。

**删除与报告不可变的关系**：合规删除是独立流程（见 `docs/09` §11.1），不是"改报告"。删除需 `admin` 发起 + 审批确认；修正报告只能新建 generation，不能用删除掩盖历史。

## 5. 存储与访问控制

- 原始 Prompt/响应仅服务内部接口可读，对外 API 不返回。
- `report_json` 与 `report_summary` 对外返回前做字段裁剪（不含内部路径、模型原始输出）。
- 数据库账号按最小权限：应用账号无 DDL 权限；迁移使用独立账号。
- 备份加密；恢复演练每季度一次。

**原始模型数据分级**：

| 数据 | 可读角色 | 说明 |
|---|---|---|
| 报告（裁剪后） | reviewer/approver | 不含原始 Prompt |
| `model_runs.raw_*` | admin/审计（按需） | 默认不对 reviewer 开放；导出需审计 |
| 附件 | 评审相关人 | 按 review 授权；不公开 URL；v1 不发送给模型 |

原始数据可脱敏（手机号/身份证/邮箱/IP）；脱敏后仍保留 `raw_*` 的哈希用于校验。导出原始数据必须记录操作人、范围、用途。

**脱敏覆盖范围**：

| 位置 | 规则 |
|---|---|
| 用例正文 | 按字段规则脱敏后再入 Prompt |
| Prompt | 不写入密钥、内部路径、无关个人信息 |
| 模型原始响应 | 存储前可脱敏；保留哈希校验 |
| 应用日志 | 不记录正文/密钥/完整响应；只记 ID 与摘要 |
| 异常堆栈 | 对外不回显；内部日志去敏 |
| 报告导出 | 与报告权限一致；敏感字段可二次脱敏 |
| Webhook | 只发摘要，不发正文 |

## 6. Webhook 安全

`options.webhook_url` 是外部回调，必须按不可信输入处理。

### 6.1 发送规则

| 项 | 规则 |
|---|---|
| 协议 | 仅 `https`；禁止 `http`、`file`、`gopher` 等 |
| 目标校验 | 域名/IP 允许列表；解析后校验非私网、非回环、非链路本地（防 SSRF） |
| 签名 | `X-Signature: sha256=<HMAC(secret, timestamp + "." + body)>` |
| 时间戳 | `X-Timestamp`，接收方校验 ±5 分钟，防重放 |
| 超时 | 连接 3s、总 10s |
| 重试 | 最多 5 次，指数退避（1s/5s/30s/2min/10min） |
| 幂等 | `X-Event-Id`（review_id + 事件类型 + generation），接收方去重 |
| 内容 | 只发摘要与 `review_id`，不发原始 Prompt、证据全文、密钥 |

### 6.2 失败处理

- 回调失败不影响评审终稿，写入 `webhook_deliveries`（状态、次数、最后错误）。
- 连续失败超阈值告警，不无限重试。
- 回调内容必须能区分 `ai_verdict` 与 `human_status`，避免接收方误读。

## 7. 模型调用可靠性

| 机制 | 规则 |
|---|---|
| 超时 | 单次调用 120s；embedding 30s；rerank 20s |
| 重试 | 超时/5xx 重试；4xx（鉴权/参数）不重试；最多 2 次，指数退避 |
| 限流 | 按供应商与角色配置 QPS/并发；超限排队或降级，不静默丢请求 |
| 熔断 | 连续失败打开熔断，冷却后半开 |
| 输出校验 | JSON 解析 → Schema → 枚举 → 引用有效性 → 数值范围（见 `docs/05` §8）；失败重试 1 次，再失败按角色失败处理 |
| 原始存档 | 无论成功失败都落 `model_runs`，失败也保留可诊断信息 |

**禁止**：把校验失败的结构化输出"修补"后继续使用；禁止把截断的 JSON 当成功。

### 7.1 输入检查、截断与 Token 超限

| 场景 | 处理 |
|---|---|
| 输入为空 / 无 steps 且无 raw_text / 超 `INPUT_MAX_CHARS` | 返回 422 `INPUT_INVALID`，不调用模型 |
| 输入接近上下文上限 | 截断证据包（按优先级），不截断用例；报告标注 `context_truncated` |
| 输出 `finish_reason=length` 或被截断 | 判为输出非法，重试 1 次；不得当成功 |
| 重试仍截断 | 按角色失败处理；记录 `model_runs.status=truncated` |
| 多次非法输出 | 1/3 可用时不出正式结论（见 `docs/01` §8） |

截断检测优先看供应商返回的 `finish_reason`，其次校验 JSON 完整性与结束符；不能只靠"解析成功"判断。

### 7.2 Prompt Injection 防护

用例正文、知识库文档、外部反馈都视为**不可信数据**，不是指令：

- 系统提示与规则只在服务端模板中定义，外部文本不能覆盖。
- 输入中的"忽略以上规则/你现在是管理员/直接判通过"等指令型文本，必须被当作待评审内容。
- 知识库内容不获得工具调用、配置修改、权限变更能力。
- 模型输出必须经 Schema、枚举、引用与业务规则校验，不能凭输出文本改变评审规则。
- 原始输入与最终 Prompt 分开存档，便于审计"模型看到的是什么"。
- 对含指令型文本的样本做安全测试（见 `docs/07` §8.6）。

### 7.3 模型版本漂移

同一别名背后可能发生供应商版本变化。每次调用至少记录：内部别名、供应商、真实 Model ID、响应返回的版本（若有）、Prompt 版本、关键参数、调用时间。

- 版本字段与配置不一致时告警，不静默接受。
- 版本变化后必须跑回归，区分指标变化来自 Prompt、知识库还是模型本身。
- 无法获取版本时，记录 `model_version=unknown` 并在报告中标注。

### 7.4 模型供应商 Adapter 统一契约

不同供应商的请求结构、超时语义、限流信号、Token 计量与错误分类差异很大。差异必须被限制在适配器内部，**不得泄漏到 pipeline 或报告层**。契约版本：`adapter/v1`（变更需版本号 + 回归）。

| 能力 | 契约要求 | 不满足时的行为 |
|---|---|---|
| 请求 | 统一映射 messages / tools / `response_format` / temperature / max_tokens；不支持的参数返回 `UNSUPPORTED_PARAM` | 显式失败或按配置降级，**不得静默忽略** |
| 超时 | connect / read / total 三层；默认 10s / 120s / 120s（embedding 30s、rerank 20s，见 `docs/06` §2） | 记 `timeout` 错误类别，按重试策略处理 |
| 重试 | 可重试：超时、5xx、429、连接错误；不可重试：400/401/403/404、内容拒绝 | 最多 2 次指数退避 + 抖动；耗尽后按角色失败（`docs/13` §4） |
| 限流 | 识别 429 与供应商限流头；按 provider 维度统一计数；有排队上限与熔断 | 不静默丢请求；记 `rate_limited`，按 `docs/20` §4 降级 |
| 模型标识 | 记录内部别名、provider、`requested_model`、`actual_model`、响应返回的版本 | 版本不可得记 `unknown` 并告警（`docs/10` §7.3） |
| Token | input / output / cached / reasoning 分开计量；供应商不返回时按估算并标 `estimated` | 报告必须标注计量来源，不能把估算当账单 |
| 成本 | 价格表带 `price_config_version`；记录 `cost_estimate` + 币种；能取得账单时记录 `actual_amount` 与结算周期；缓存命中与失败调用单独计 | 历史报告成本不因新价格被重算（`docs/20` §6.3） |
| 异常 | 统一分类：`auth` / `quota` / `content_filter` / `invalid_request` / `output_invalid` / `timeout` / `rate_limited` / `server` / `unavailable` | 映射到 `docs/19` 错误码，不透传供应商报文 |
| JSON 能力 | 标注 `native_schema` / `json_mode` / `prompt_only`；记录结构化输出合规率 | `prompt_only` 必须走输出校验 + 重试（`docs/18`） |
| 可观测性 | 每次调用记录 request_id、provider、model、latency_ms、attempt、tokens、error_class、http_status | 缺字段视为实现缺陷，不是"可选优化" |

**返回策略**：

- 适配器返回**标准化响应**（统一字段 + 错误类别），同时保留必要的原始响应元数据（http_status、request id、finish_reason、usage、model version）。
- 原始请求/响应正文写入 `model_runs.raw_*`，仅 `admin`/审计可读，按 `docs/10` §4.3 脱敏与保留；对外接口只返回标准化字段。
- 两者都保留但分层存放：标准化响应供业务使用，原始元数据供问题追溯；不得把原始报文直接拼进报告。

**禁止**：适配器内拼接业务 Prompt、修改业务结论、自行选择模型（模型由 `router` 按 `models.yaml` 决定）、在重试中切换供应商（备用模型必须在创建任务时冻结，见 `docs/20` §4）。

**验收**：每个真实模型接入产出 `models/<provider>-<model>-<date>.json`（`docs/06` §3.6.2），并有 `tests/llm/test_adapter_contract.py` 覆盖超时/重试/限流/错误分类/Token 计量/原始元数据保留。

## 8. 任务恢复与幂等

- 队列：PostgreSQL 持久化 + `FOR UPDATE SKIP LOCKED` + 租约（见 `docs/01` §9）。
- 超时：单次 120s、阶段级、任务 20 分钟、租约 5 分钟（见 `docs/13` §3）。
- Checkpoint：每阶段成功写 `review_stages`；重试从最后成功阶段恢复，不重跑已成功阶段。
- 重复领取：终稿写入前校验 `status`、`attempt` 与 `generation`，已有终稿则丢弃本次结果。
- 重复提交：同一 `idempotency_key` 复用已有报告（200 + 真实状态 + `idempotent_replay`）；`force=true` 在旧代次终态后新建 `generation`（202），旧代次仍在运行时返回 409 `REVIEW_IN_PROGRESS`（见 `docs/03` §1.1）。
- 幂等键必须覆盖：用例内容、`test_scope`、`automation_context`、影响结论的 options、Rubric/Prompt/KB/Embedding Profile/检索配置版本（见 `docs/02` §3）。
- 部分唯一索引 `WHERE superseded_by IS NULL` 保证同一时刻只有一个 active 版本；同一 key 的并发提交按 key 串行化（见 `docs/24` §4.1），未 force 的后到者按幂等命中返回，并发 force 的后到者按 S7 拒绝，**不返回 409 `DUPLICATE`**。

### 8.1 任务状态转换

| 当前 | 允许转到 | 触发 |
|---|---|---|
| `queued` | `processing` / `failed` | 领取 / 入队校验失败 |
| `processing` | `retrying` / `done` / `completed_with_warnings` / `failed` | 失败待重试 / 完成 / 降级完成 / 不可恢复 |
| `retrying` | `processing` / `failed` | 重试领取 / 超过最大次数 |
| 租约过期的 `processing` | `queued`（或 `retrying`） | 恢复任务重新入队 |
| `done` / `completed_with_warnings` / `failed` | 无（终态） | — |

规则：

- 终态不允许直接回到 `processing`；要重评必须新建 generation。
- 重试产生新的 `model_runs`（`attempt` 递增），不复用旧调用记录。
- 同一任务重复领取时，写入终稿前校验 `status` + `attempt` + `generation`。
- v1 不提供主动取消接口；需要终止只能等超时或失败，后续版本再设计。

## 9. 降级策略

降级矩阵见 `docs/01` §8，原则：

- 核心评审（主审盲评/仲裁）失败 → 任务失败，不出正式结论；
- 单角色失败 → 允许降级，但报告标注、`participants` 减少；
- 投票缺失 → 对应维度 `not_assessed`，不得伪造；
- Embedding/Rerank 失败 → 可降级检索，标注通道；
- 知识库不可用 → 不得声称"知识库证实"。

降级报告可被人工批准（见 `docs/09` §7），但批准不改变降级标记。

## 10. 成本与预算

### 10.1 记录

- 每次调用：输入/输出 token、模型、供应商、延迟、`cost_estimate`、`currency`、`price_config_version`。
- 每次评审：累计成本、token 总量。
- 每批次/每日：汇总成本与预算使用率。

### 10.2 控制

| 层级 | 预算 | 超限行为 |
|---|---|---|
| 单次评审 | `REVIEW_BUDGET_TOKENS` / `REVIEW_BUDGET_COST` | Reranker 可跳过；**投票不可静默跳过**：预算不足以覆盖投票时，受影响候选标 `need_human`、任务标 `completed_with_warnings`，不出正式完整结论 |
| 单批次 | `BATCH_BUDGET_COST` | 拒绝新任务入队，返回 429 |
| 每日 | `DAILY_BUDGET_COST` | 告警 + 降级或暂停，按配置 |
| 重试 | `QUEUE_MAX_ATTEMPTS` | 超限失败，不无限重试 |

成本只估算不保证与账单一致；`price_config_version` 用于解释差异。

## 11. 日志与审计

### 11.0 可观测性

每个任务必须能按 `review_id` 串起全链路：

| 指标 | 用途 |
|---|---|
| 阶段成功率 / 耗时（P50/P95） | 定位慢阶段 |
| 各模型调用成功率、429 比例 | 供应商健康度 |
| 平均 token、单条成本 | 成本控制 |
| 队列等待时间、超时率 | 容量与阈值 |
| Checkpoint 恢复成功率 | 恢复机制有效性 |
| 检索降级率 | KB/索引健康度 |
| 人工复核积压量 | 运营负载 |
| `need_human` 比例趋势 | 模型/知识库/Rubric 是否改善 |

日志带 `trace_id`（= review_id + stage + attempt），可从 API 一直追到模型调用。

### 11.1 日志

- 结构化日志（structlog），字段：`review_id`、`stage`、`role`、`model`、`attempt`、`latency_ms`、`status`、`degraded_reasons`。
- 不记录用例正文、Prompt 全文、模型响应全文、密钥。
- 错误日志带 `error_code`，不返回堆栈给调用方。

### 11.2 审计

`audit_log`（只追加）：

| 事件 | 必填字段 |
|---|---|
| 人工决定 | review_id、decision、reviewer、reason、previous_verdict |
| 强制重跑 | review_id、generation、caller、reason |
| 知识库发布/回滚 | kb_version、from/to、operator、回归结果 |
| 模型/Prompt/Rubric 变更 | 变更项、旧/新版本、operator |
| 权限变更 | 对象、操作、operator |

审计日志只读，保留 ≥ 1 年。

## 12. 部署与依赖

- 数据库不暴露公网；连接强制 TLS（生产）。
- 容器以非 root 运行；镜像固定 digest。
- 依赖锁定版本，定期扫描漏洞。
- 生产与测试使用不同 Key、不同数据库、不同 webhook secret。

## 13. 验收要点

见 `docs/07` §8.6，至少覆盖：

- 模型超时/5xx/4xx 的重试与失败语义；
- 输出 Schema 校验失败不进入融合；
- Worker 被杀后任务恢复且不重复出终稿；
- 幂等键对 `NULL` 字段与 `force` 的行为；
- Webhook 签名、重放、SSRF、失败重试；
- 日志不含密钥与用例正文；
- 成本记录可汇总、可解释。
