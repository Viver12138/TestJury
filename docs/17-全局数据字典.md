> 版本：v0.8 · 2026-11-10（v0.8：跨文档冲突清理与 P0 决策冻结）
> 目的：统一所有模块的枚举、字段含义、可空规则与映射，避免 02/03/11/16 各自维护一套。

## 1. 评审任务

| 枚举 | 取值 | 说明 |
|---|---|---|
| `review_jobs.status` | `queued` / `processing` / `retrying` / `done` / `completed_with_warnings` / `failed` | 单任务执行状态 |

| `review_stages.stage` | `input_check` / `preprocess` / `kb_retrieve` / `blind_review` / `fusion` / `vote` / `arbitration` / `verdict` / `render` | 阶段；**不含 `done`**（`done` 是任务状态） |

| `degraded_reasons` | `kb_module_missing` / `raw_text_unparsed` / `vector_unavailable` / `keyword_unavailable` / `rerank_skipped` / `model_missing` / `scope_missing` / `automation_context_missing` / `budget_exceeded` / `arbitration_skipped` | 降级原因 |

## 5. 角色与权限

| 角色 | 系统权限 | 知识库权限 |
|---|---|---|
| `reviewer` | 提交评审、issue 反馈、request_changes | — |
| `approver` | 上述 + approve/reject | — |
| `admin` | 系统配置、模型配置、强制重跑 | 可管理账号 |
| `kb_creator` | — | 创建/修改 `draft` |
| `kb_reviewer` | — | 审核 → `reviewed` |
| `kb_publisher` | — | 发布/废弃/回滚 |

- `admin` 不自动获得 `approver` 或 `kb_publisher`。
- 一个身份可绑定多个角色，但必须服务端授予。
- 生产环境 `kb_creator` 与 `kb_publisher` 不得为同一人（可配置）。

## 6. 可空与默认值

| 字段 | 可空 | 默认 | 说明 |
|---|---|---|---|
| `case_version` | 否 | 1 | 调用方可传；不传视为 1 |
| `test_scope` / `automation_context` | 是 | null | 缺失限制结论强度 |
| `candidate_id`（issues） | 是 | null | 主审补充问题可无候选 |
| `issue_votes.severity` | 是 | null | validity != accept 时为空 |
| `confidence` | 是 | null | 未校准 |
| `report_locked_at` | 是 | null | 非空即不可变 |
| `review_decisions.reason` | 是 | null | reject/request_changes 必填（应用层） |

## 8. 变更与兼容

- 新增枚举值必须同时更新：本文件、数据库 CHECK、Pydantic Enum、Prompt 枚举、验收用例。
- 删除/重命名枚举值属于破坏性变更：需迁移 + 版本号 + 回归。
- 旧报告按 `report_schema_version` 读取，不按新枚举强转。
- 本文件的枚举与 `docs/02` DDL、`docs/03` API Schema 不一致时，以本文件为准并修另外两处。
