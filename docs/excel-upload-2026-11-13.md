# Excel 用例上传与批量评审

> 版本：v1.13（设计基线；2026-11-13 按用户要求新增本地上传入口）

本地页面的用例提交区只保留文件上传、模板下载和只读预览，移除标题、前置条件、步骤等手工录入表单。历史报告、逐条报告下载和反馈继续保留。本机访问凭证暂时关闭，无需输入密钥。

## 使用方式

打开 `http://127.0.0.1:8088`，选择或拖入一个 Excel 文件。文件解析成功后展开预览核对内容，点击“开始批量评审”。页面显示各用例进度，完成后点击“查看报告”并下载。刷新页面可恢复当前批次进度。

报告下载也使用 **Excel（.xlsx）**：查看单条结果后点击“下载 Excel 报告”，或在批次进度下点击“下载整批 Excel 报告”。整批导出保留尚未完成、失败和已取消的用例；这是点击时的进度快照，完成后可再次下载。

工作簿包含“评审汇总、用例步骤、问题明细、知识依据、导出说明”：可查看原始操作与预期、结论、严重程度、原文引用、修改建议、知识来源及人工审批状态。支持筛选、冻结表头、自动换行。超长内容会分段保存在“长文本”表；文本不会被解释为 Excel 公式。

- 支持 `.xlsx`、`.xls`，最多 10 MB、50 条用例、20 张工作表；工作簿总行数不超过 5000，每张表不超过 100 列。
- 可从页面下载 `TestJury-template.xlsx`。建议列：用例编号、用例标题、前置条件、操作步骤、预期结果。其中用例标题和操作步骤列必需；预期为空会保留并提示，不自动补写答案。
- 兼容“用例名称/标题”“测试步骤/执行步骤”“期望结果/预期”等常见列名。表头可位于前 20 行，工作簿内所有非空工作表都需符合导入格式。
- 一行一条用例，或同一用例连续多行均可。多行步骤可以重复相同编号、标题，也可以将编号和标题合并单元格；后续空标题、相同或空编号行归入上一条用例。空行结束该连续用例。
- 操作与预期单元格若均有数量一致的非空多行，则逐行对应；数量不同会保留完整单元格作为一个组合步骤，不猜测对应关系。
- 可选列包括模块、项目 ID、产品版本、测试数据；其他具名列保留在测试数据中。默认 `minishop / order / 1.0.0 / api / current_implementation / functional`，当前知识库仅支持已启用范围。
- 同一编号不得跨工作表或非连续出现；缺标题、缺操作、超限、损坏或加密文件会明确拒绝，解析失败不创建评审任务。隐藏工作表需要先删除或取消隐藏。
- `.xlsx` 中的公式须先粘贴为值；`.xls` 的公式按文件已保存结果读取，上传前应重新计算并保存。宏不会执行，不接收 `.xlsm`。

## 接口与本地访问

- `GET /v1/imports/excel-template`：下载公开空白结构加示例模板。
- `POST /v1/imports/excel`：multipart 文件字段 `file`，返回解析用例、工作表/行号、内容摘要与提示；只预览，不调用模型，也不持久保存原工作簿。
- 页面确认后调用既有 `POST /v1/review-batches`，以严格知识模式创建批次，保留原预算、逐条版本冻结和幂等控制；相同文件重复提交复用已有结果。
- `GET /v1/reviews/{review_id}/report.xlsx` 下载单条 Excel 报告；`GET /v1/review-batches/{batch_id}/report.xlsx` 下载整批 Excel 报告。导出不重新评审，不调用模型，不改写原始记录。原 Markdown 接口继续兼容既有客户端，网页下载改用 Excel。
- 原文件的 SHA-256、工作表名、行号保存在每条用例的测试数据中，用于追溯。后续评审记录按既有规则持久保存。

`scripts/serve_local.py` 默认启用本机免凭证，服务仍监听 `127.0.0.1:8088`。调用者记录为 `local-reviewer` 服务身份，仅具有 reviewer 权限；不能冒充人工审批或修改知识发布状态。只接受直连回环地址和同源浏览器请求，不信任转发地址。

通用应用配置 `LOCAL_ACCESS_WITHOUT_KEY` 默认 false，生产模式禁止开启。要恢复本机凭证要求，在启动前设置 `LOCAL_REQUIRE_API_KEY=true`；此时可继续用带 Bearer 凭证的 API 客户端访问。当前网页按本机免凭证场景提供，不显示凭证输入框。

此功能由用户明确要求，属于本地技术预览调整。生产补齐仍暂缓，原 AI 黄金集、自动融合重复项及独立性限制不因此改变。
