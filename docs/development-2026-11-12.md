- 独立盲评、投票、条件仲裁、引用验证、报告追溯、后台并发与租约续期。
- 中文网页提交、进度、历史和报告下载；问题级反馈保存身份及历史，不改变原始报告、人工审批或黄金集。
- 网页可提交采纳、误报、漏检反馈并查看历史；知识待核实按项目聚合报告中的证据线索，保持假设身份，不自动写成业务规则。
- 成功的检索、每个角色盲评、融合、每张投票和仲裁输出可持久化恢复。摘要绑定用例、上游输出、知识、运行配置与实现；旧执行者不能保存恢复点，候选编号和历史模型调用保持稳定。投票轮中断后只重新执行未保存的票；外部调用成功但尚未保存恢复点的窗口仍不能保证恰好一次。
- 聊天模型每次尝试调用前原子预留 token 与估算费用，限制单条、批次和 UTC 每日额度；并发任务及重试共享持久账本，未知结果保留预留。超限不发送调用，缺席投票保留为未评估，不伪装为反对。批次在任务入队时即绑定，避免执行时尚未归属批次而漏算。
- 提交入口在每日或批次额度已耗尽时返回 429，保留已有请求重放；拒绝强制重评时不替换旧任务、不创建半成品。同一任务的并发预留不足时等待在途调用结算，失败或取消调用的未知费用仍保留。
- 检索版本 `hybrid-bm25-rrf-4` 为显式接口保留匹配的需求行为说明，按不同接口选择契约，避免测试数据示例重复占位；预览用例在 4 个片段内包含不建单、不占券等行为。知识内容与黄金集标签未因此改写。
- 盲评、投票、仲裁不再接收用例管理编号与修订编号，业务对象 ID 和产品版本保留；防止 `negative` 等编号后缀干扰判断。明确问句标题、框架能力声明和额外字段不自动构成缺陷。
- 相同错误状态码与文案可在同一引用及知识依据下合并；查询条件中的 ID 不再被当成修正值，不同对象或冲突修正仍保持独立。知识原文引用保存在模型意见中供追溯；知识引用正确也不能掩盖不存在于用例中的证据原文。
- 完成通知采用持久投递队列、稳定事件 ID、HMAC 签名、有限重试和发送租约。只发结果摘要；要求 HTTPS 与允许列表，解析后排除受限地址并固定连接 IP，不跟随重定向。默认关闭，未配置时提交通知地址会明确报错。

## 本地使用

服务地址：[http://127.0.0.1:8088](http://127.0.0.1:8088)。按用户最新决定，当前采用 Qwen + DeepSeek 真实双模型评审；应用、环境示例、本机和评测默认均为 `dual`。Kimi 暂停使用。双模型沿用既有保守裁决规则，两方分歧仍留待复核。

访问凭证在 `.tmp/local-access.json`，只复制 `key` 值到网页。该文件已被 Git 忽略。数据库由 `testjury-postgres` 容器提供，应用运行于本机 Python。此前应用 Docker 镜像通过存活、数据库健康和非管理员用户检查；证据及源码校验值见 `evidence/M2/container_smoke.json`。容器冒烟使用 Mock 且关闭 Worker，仅证明部署启动，不代替真实模型验收。今天收尾时，本轮质量修复的镜像已构建成功，但尚未重新执行容器冒烟或重启本地服务；现有服务仍运行此前 `19e418e` 的代码。

启动命令：

```powershell
.\.venv\Scripts\python.exe scripts/serve_local.py
```

默认读取 `.tmp/knowledge-vector-release-final.json` 和 `evidence/M2/acceptance/` 中对应验收文件。可通过 `LOCAL_KNOWLEDGE_RELEASE` 指定其他候选。脚本仅在尚无启用版本时初始化；已有版本通过带权限和并发保护的知识接口切换。

完整测试使用 `scripts/verify_isolated.py`，它新建临时数据库并在结束后删除该临时库。禁止以应用数据库运行会重建 schema 的测试。

## 黄金集修订与效果解释

v1 保留原始种子；v2 补足真正执行的动作和夹具关系；v3 为负例补齐每个已执行观测的预期，保留有意植入的业务冲突。v2 部分负例同时包含未标注的缺失断言，因此不能把其所有额外发现计为误报。所有版本都保留、按文件哈希区分，三版均为已见的代理编写种子，不是独立盲集。

接口契约检索修复后，v2 的金额与支付重试两个正例一轮均零问题，两个反例均找到植入冲突，但仍有重复与仲裁失败。后续 v3 的金额正例又出现把显式夹具误当默认种子的误报，说明模型仍有波动。已补充夹具与默认种子的解释边界，不将单轮成功宣传成效果验收完成。离线 Mock 的 30/30 报告只验证流程，不代表识别率。

v3 历史开发集诊断（`d920136a7736…`）：6/6 生成报告，3/3 植入错误得到类别级匹配，3 条预设正确用例中 2 条被提出问题，总计 12 条发现。发生在显式夹具政策补充和恢复功能加入之前，保留作历史比较。

v3 全量双模型诊断（`dual-e29585b1afc7`，对应 `19e418e` 实现）：30/30 生成报告，15/15 植入错误得到类别匹配；29/30 评审完整，G-012-negative 因预算不足缺席投票及仲裁。15 条预设正确用例中 3 条被提出问题，其中 G-006 是黄金集自身遗漏，G-007 是不必要的审计字段要求，G-010 是没有充分依据的文案建议且系统保留分歧。总计 36 条发现中还含重复和负例上的额外误报，不能把类别匹配率 100% 当作准确率或上线依据。

v4 只修订已经核实的 G-006 数量观测遗漏，不为了迎合模型扩展其他用例的范围。原 v3 数据、报告与失败记录保留。后续复测范围由结果目录中的用例数与代码指纹确定，不将部分复测描述成 v4 全量重跑。
