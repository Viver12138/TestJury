# MiniShop 下单缺陷用例与知识库对比评审

本目录交付 10 条有意带缺陷的下单用例，以及同一输入在知识库启用、禁用条件下的 20 份真实双模型评审。原始意见保留，不根据评审结果修改输入或预埋标注。

## 交付文件

- `MiniShop_下单功能_10条带缺陷测试用例.xlsx`：可上传至用例提交页面，包含 10 条用例、11 个步骤行；不含缺陷答案。
- `MiniShop_下单10条缺陷用例_知识库启用禁用评审对比.xlsx`：包含对比总览、逐条对比、缺陷标注、两组问题明细和知识依据、原始用例、逐条 AI 复核、运行与限制。
- `cases-and-annotations.json`：冻结输入与单独保存的预埋主缺陷。标注不传给模型。
- `source-facts-verification.json`：在归档源码和独立夹具上通过的 15 类业务事实探针，不访问原项目数据库。
- `runs/live-35a075a1a3/`：本次真实运行的调度清单、20 份完整原始记录、复核记录、统计及工作簿校验回执。

`Mock_流程自检_非实际评审.xlsx` 和 `runs/mock-*` 是本机流程自检产物，不作为真实效果结果交付或提交。

## 方法与限制

- “启用/禁用数据库”按本次讨论语境指**知识库**。保存任务的 PostgreSQL 数据库两组均开启；使用同一独立临时库，结束后已清理，本机应用库未改动。
- 两组实际使用 `qwen3.8-max` 与 `deepseek-flash`，角色仅 `chief_blind`、`jury_a`。模型注册表中保留的 Kimi 配置没有被调用。Reranker 两组均关闭。
- 同一用例的请求内容、输入哈希、Prompt、Rubric、模型配置和预算相同。每对用例内的条件先后顺序按固定种子 `20261113` 随机安排，并发为 2。
- 每条预算上限为 60000 聊天 Token、估算费用 2 元；账面费用基于未核对供应商账单的配置价格，不含向量查询费用，不作为供应商实扣账单。
- 业务基线为 MiniShop `e354437069504381f10a54d9c14baed755f3ba56` 的当前实现，参考 RULE-ORDER-001～006。20 轮评审针对用例文字，没有向正在运行的 MiniShop 服务实际下单；业务事实另通过归档源码探针核验。
- 用例和逐条技术复核均由开发者 AI 完成，无独立人工盲标。全部样本原本都带缺陷，不能计算真实误报率，也不能将本次结果外推为总体准确率。
- 原报告状态、严重程度、模型意见及知识引用校验结果保留。复核指出重复、额外建议和限制，不代替缺失投票，不将待复核项改成已确认。

## 核验与重新导出

`adjudication.json` 绑定每份原始结果文件的 SHA256、冻结数据集及事实探针记录。导出器验证这些哈希、两组输入/请求一致性、知识版本和全部问题的复核覆盖，所有文本单元格禁止按公式执行。

从仓库根目录执行下列命令即可重新导出，不调用模型：

```powershell
python scripts/export_order_comparison.py --run outputs/order_knowledge_comparison_2026-11-13/runs/live-35a075a1a3 --adjudication outputs/order_knowledge_comparison_2026-11-13/runs/live-35a075a1a3/adjudication.json
```

如需重新运行真实模型实验，使用 `scripts/compare_order_knowledge.py --mode live --cases ... --release ...`，需要本机供应商凭证、可创建临时库的 PostgreSQL 和已验收的知识发布文件；会产生费用，模型采样也可能产生不同结果。此交付没有为了提高检出数重复运行真实实验。
