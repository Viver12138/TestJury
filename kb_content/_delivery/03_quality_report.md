对 37 份带 YAML Front Matter 的知识文档执行：

2. 枚举合法性（`knowledge_type`、`source_type`、`evidence_level`、`status`）；

- 核对接口字段与 Pydantic/序列化函数；
- 核对“明确不支持”是否有代码证据；
- 核对推断内容是否标记为 E4/未决。

## 5. 质量风险与未覆盖项

### 5.1 阻断正式评审的问题

1. **没有 E1**：所有规则来自 README + 代码，未经业务负责人确认。
2. **复核前没有 approved**；2026-11-12 复核后 24 份 approved、13 份 in_review 待复审。
3. **没有正式 PRD**：需求是反向整理，不是原始需求。
4. **没有 Git commit**：无法用 commit 追溯知识版本。
5. **没有测试用例/黄金集**：无法做检索回归和 K0/K1 对照。

### 5.2 内容质量风险

1. **需求解释风险**：`REQ-ORDER-*` 是对代码行为的归纳，可能把“实现现状”误当成“产品意图”；已用冲突 C-01/C-02/C-09 标记。
2. **状态机风险**：`REFUNDING → PAID` 与 `PENDING_SHIPMENT` 不可达是当前实现事实，不代表产品设计；已标记冲突 C-04/C-10。
3. **券语义风险**：`total_quantity` 的发放/使用语义不清；已标记 C-06、Q-06。
4. **支付展示风险**：多支付记录与单对象关系；已标记 C-07、Q-05。
5. **统计口径风险**：销售额含退款单；已标记 C-08、Q-09。
6. **环境风险**：Docker 构建缺 `seed_media`；已标记 C-05、GAP-014。
7. **数据时效风险**：当前库券有效期按 2026-09-21 播种；跨日期执行会变化。
8. **行号漂移风险**：`source_ref` 行号只校验范围，未校验行内容；代码修改后需重新生成锚点。
